# Super-Org 项目协作指南

## 从讨论形成行动项

先讨论团队要解决的问题，把确认过的目标、决定、分工和可检查的产出写成纪要。在已配置的钉钉建项群先 @ 机器人发送「登记项目成员」，再提交以「项目会议纪要」开头并含一行「项目名称：…」的首次纪要。也可以在工作台创建项目再录入任务。首次群聊建项进入待开工状态，Agent 整理现有共识并指出阻碍开工的问题。会议录音可以先在外部转写，再提交文字纪要。 [部署与运维](deployment.zh-CN.md)

任务至少应有标题和可验收的产出。可以指定负责人、依赖和里程碑。「项目成员」里的「添加项目 Agent」会把当前项目 Agent 加到成员列表，之后可以像指派其他成员一样指派给它。钉钉身份可根据实际群消息登记，手填 GitHub 账号属于名册资料。仓库反馈的操作授权还取决于 GitHub 来源策略。

仓库是项目的可选关联。在「项目设置」填写 `owner/repository`，不同项目可以关联不同仓库。任务可以只在工作台存在，也可以从 Issue 建立、补充链接，或在群里引用任务并请 Agent 新建 Issue。出现多个可能的任务时，Agent 应先确认指的是哪项。

## 开工和调整计划

项目开工后，负责人可以在看板或群里开始任务。项目 Agent 也能直接记录进展和提交结果。需要后台协助时，运行层可以按授权安排执行，也可以在任务的「Agent 执行」区域选择「委托后台执行」。工单挂到原任务，保留原负责人。

已绑定项目的群里可以引用消息、使用任务名或明确的任务引用提出修改，日常交互使用自然语言。Agent 读取最新板面、调用实际项目工具并报告结果。比如「把验收条件加上移动端滑动，先记下来，等讨论确认后再开工」应只更新验收条件。相同的项目操作也可以在工作台完成。 [项目 Agent 工具](events/project-tools.zh-CN.md)

计划可以随讨论更新。若调整会改变正在执行的交付范围，先停下这轮执行，再修改范围。新增任务、改分工和启动工单是各自独立的操作。

## 跟进与验收

- 在任务详情查看执行记录、真实报告、待回答问题和交付。对正在运行的工单补充要求时，继续原工单。
- 在任务详情或项目群记录实际进展。可以在「项目设置」为每个项目设置自动检查的时区、时间和工作时段，也可以主动要求跟进一项任务。等待依赖时，可继续汇报已经做完的准备工作。 [任务进展与跟进](events/task-tracking.zh-CN.md)
- 在全局「Agent 状态」查看本机 Agent、Worker 并发、排队数、钉钉连接和各仓库监听状态。
- 项目开启自动推进后，依赖解除、阻塞和预约到期可以唤起同一个 Agent。它按授权读现状、启动就绪任务或跟进原工单。只读检查没有发现变化时可保持安静。 [自主跟进](events/follow-up.zh-CN.md)
- 成员提交结果，或关联工单报告成功且所需证据齐备时，系统登记交付并创建对应版本的验收任务。在看板给验收任务指定负责人，在该任务里提交通过或退回的依据。 [交付与验收](events/delivery.zh-CN.md)
- 验收通过后任务完成。显式标为「负责解决」的 Issue 可以随验收同步关闭，仅参考的 Issue 保持独立。PR 评审可触发技术答疑或修改，改动继续原工单，实际结果回到原 PR 或行讨论。 [仓库协作](events/repository.zh-CN.md)

判断一次操作是否成功时，打开左栏「推进记录」查看触发事件、Agent 决定、工具结果和投递回执。发送接口接受只代表消息已提交给平台。 [推进记录](events/project-history.zh-CN.md)
